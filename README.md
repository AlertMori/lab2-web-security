# Лабораторная работа 2 — уязвимое веб-приложение, эксплуатация и патчи

Учебный проект по технологиям и программированию. Веб-приложение на Python
(Flask) с тремя **намеренно** оставленными уязвимостями из OWASP Top 10,
скрипты их эксплуатации на Python и патчи в формате diff.

> ⚠️ Приложение заведомо небезопасно. Запускать **только локально**
> (127.0.0.1) или в изолированной виртуальной машине. В интернет не выставлять.

## Структура

```
lab2/
├── app/                      # Часть 1: уязвимое веб-приложение
│   ├── app.py                #   Flask-приложение (гостевая книга, вход, поиск, кабинет)
│   ├── init_db.py            #   создание и наполнение БД (SQLite)
│   ├── requirements.txt
│   └── templates/            #   HTML-шаблоны (Jinja2)
├── exploits/                 # Часть 2: эксплуатация на Python
│   ├── exploit_sqli.py       #   SQL-инъекция
│   ├── exploit_xss.py        #   хранимая XSS
│   └── exploit_idor.py       #   IDOR / нарушение контроля доступа
├── patches/                  # Часть 3: исправления
│   ├── 01-fix-sqli.diff
│   ├── 02-fix-xss.diff
│   └── 03-fix-idor.diff
└── README.md
```

## Уязвимости (OWASP Top 10 2021)

| № | Уязвимость    | Категория OWASP                     | Где в коде                                      |
|---|---------------|-------------------------------------|-------------------------------------------------|
| 1 | SQL Injection | A03:2021 — Injection                | `app.py`, функции `login()` и `search()`        |
| 2 | Stored XSS    | A03:2021 — Injection                | `templates/index.html` (`{{ c.body \| safe }}`) |
| 3 | IDOR          | A01:2021 — Broken Access Control    | `app.py`, функция `account()`                   |

**1. SQL-инъекция.** Пользовательский ввод подставляется прямо в текст
SQL-запроса через форматирование строки. Это позволяет обойти вход без
пароля (`admin' -- `) и выгрузить все логины и пароли через `UNION SELECT`
на странице поиска.

**2. Хранимая XSS.** Текст комментария выводится в шаблоне с фильтром
`| safe`, то есть без экранирования. Внедрённый `<script>` сохраняется в БД
и выполняется в браузере каждого, кто откроет главную страницу.

**3. IDOR (небезопасная прямая ссылка на объект).** Эндпоинт `/account`
берёт идентификатор аккаунта из параметра запроса `?id=` и не проверяет,
принадлежит ли аккаунт текущему пользователю (и вообще не требует входа).
Перебрав id, можно прочитать секрет любого пользователя.

## Запуск (часть 1)

```bash
cd app
python -m pip install -r requirements.txt
python init_db.py          # создаст lab.db
python app.py              # http://127.0.0.1:5000
```

Тестовые учётные записи: `admin / S3cr3tAdminP@ss`, `alice / qwerty123`,
`bob / password`.

## Эксплуатация (часть 2)

Приложение должно быть запущено. В другом терминале:

```bash
cd exploits
python exploit_sqli.py     # обход входа + выгрузка паролей
python exploit_xss.py      # внедрение <script> в гостевую книгу
python exploit_idor.py     # чтение секретов чужих аккаунтов по id
```

## Исправление (часть 3)

Патчи применяются из корня репозитория:

```bash
git apply patches/01-fix-sqli.diff
git apply patches/02-fix-xss.diff
git apply patches/03-fix-idor.diff
```

Суть исправлений:
- **SQLi** — переход на параметризованные запросы (placeholder `?`): значения
  передаются драйверу отдельно от текста SQL, кавычки во вводе больше не
  влияют на структуру запроса.
- **XSS** — убран фильтр `| safe`; Jinja2 по умолчанию экранирует вывод,
  поэтому `<script>` превращается в безобидный текст `&lt;script&gt;`.
- **IDOR** — личность берётся из серверной сессии, а не из параметра запроса;
  требуется вход, и пользователь видит только свой аккаунт.

После применения патчей пересоздайте БД (`python init_db.py`), перезапустите
приложение и снова запустите эксплойты — все атаки больше не проходят
(проверено).
